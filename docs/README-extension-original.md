# 価格DB+ 券後最安

在 DLsite 作品页显示**含优惠券的最低价**、记录价格、并可试算**多部购买**，界面语言跟随 DLsite 当前显示语言。

基于已安装的「インディー価格DB」扩展（`ikpcogdfipkelndejkbbbokdedfjfoji`）重构：保留它的价格推移数据源，补上券后价、口径分层、组合明细与多部折扣。

## 安装

1. `edge://extensions/`（Chrome 用 `chrome://extensions/`）→ 开启「开发人员模式」
2. 「加载解压缩的扩展」→ 选择本目录 `H:\Dlsite\dl-ext\price-db-plus`
3. 打开任意 DLsite 作品页

原版扩展可保留（面板 id 不同，互不干扰），也可停用。

## 两档价格口径

| 行 | 含义 |
| --- | --- |
| 券后价格 | 页面自己算出的「一番お得なクーポン利用価格」，含你账号能用的全部券 |
| 最低价（含活动券） | **新用户券不计入**，只算活动券/通用券，按当前作品价格算出 |
| 理论最低（含资格券） | 把渠道券、购买历史券、个人券也纳入的理论下限 |
| 无券历史最低 | 不含券的历史最低 |
| 全期间最低 · DLsite / FANZA | 服务端历史（インディー価格DB），不含券 |

券按三种归类，只有第二类进入「最低价」：

- `newuser` — 券名含「新規ユーザー」「ユーザー登録特典」等，一次性，**不进最低价**
- `qualified` — 需购买历史 / 渠道 / 支付方式资格（`issue` 里是 `product_id`、`specific_route`、`baitai`、`price_sum`），只进理论最低
- `campaign` — 其余（含期限活动券），进最低价

「理论最低」还会与页面显示值取更小者——页面可能用到了你账号里的个人券，那是真实可用的更低价格。

## 点击「查看组合」

浮层里按 DLsite 的真实计算顺序列出：

```
定価 → 店铺折扣 → 券 → 最低价
```

并列出**没被采用的券**及原因分组（新用户券 / 需资格券 / 条件不符），例如「【3作品以上購入で利用可】90%OFF」在买单部时会被明确标为条件不符。

实测校验：定価 1,980 → 社团折扣 10% → 1,782 → 券 −300 → **1,482**，与页面「一番お得なクーポン利用価格」一致——**券作用在打折后的价格上**。

## 多部购买

按钮上直接显示最优单价（如「多部购买 · 3 部 ¥4.64」），点开是 1~5 部的总价与单部均价表。规则依据官方文档 [「まとめ買い」と「セット割」の違い](https://cs.dlsite.com/hc/ja/articles/17909850923801)：

- 券的门槛写在 `post_condition.count`（如「3 作品以上可用」），部数不够就不计
- 一旦 まとめ買い / セット割 成立，**其他折扣全部作废**；セット割 的折扣率按**定価**计算
- 但券在它们之后**仍可继续扣减**
- 定額券（`discount_type: price`）按整单只扣一次，不是每部都扣

实测（BJ078576，定価 1,100 円）：单部用 15%OFF 活动券 → 935 円；3 部起触发「3 作品以上 90%OFF」→ 总价 139→**14 円**（单部 4.64），与公式吻合。

## 多语言

显示语言按 `?locale=` → `<html lang>` → cookie `locale` → 浏览器语言 依次判定（cookie 在切换语言时不更新，故排在后面）。支持 DLsite 语言切换器的全部 14 种语言；金额按语言习惯格式化（`580円` / `¥24.46` / `4,53 €` / `Rp 100.894`）。设置页可固定语言。

## 购物车：最省钱的拆单方案

购物车页（`/maniax/cart`）会多出一块面板，告诉你**一起买**和**拆成几单**哪个更便宜，并给出可操作步骤。

两个已确认的 DLsite 限制决定了实现方式：

- **购物车没有部分结算**，所以要拆单只能「把商品移到『稍后再买』→ 结算 → 再移回」
- **一次结算只能用一张券**（内部名 `selectedCoupon` 是单数）

券用的是你账号里真实持有的券（`/maniax/mypage/coupon/list/ajax`，含 `is_multiple_use` 是否可重复使用、`post_condition.count` 本数门槛），不是公开券池。

实测验证（4 件商品、真实券）：

| 方案 | 金额 |
| --- | --- |
| 一起买（15% 券） | 2,618 円 |
| 拆单：一水社 3 件（90% 券）+ 其他 1 件（15% 券） | **968 円** |

省的 1,650 円来自 90% 券的本数门槛——它要求「対象作品を3作品以上購入」，混进非对象作品就用不了，所以必须把 3 件一水社单独结一单。算法枚举全部划分方式（≤9 件穷举，超过则贪心），并对一次性券做冲突消解。

**每个批次用一个颜色标记**：批次标题、该单的每件商品、所用券、节省额、以及下方操作步骤里的那一行，全部是同一个色块（共 8 色循环），照着颜色把商品分组去点「稍后再买」即可。

**内訳随时可看**：即使算下来拆单不划算，也能点开看「一起买 vs 拆单」的对比和每一单的金额，判断依据不藏起来。

> 实现上有个坑值得记下来：购物车行的 `data-custom-genres` **恒为空数组**，`data-work-options` 也和作品页不一致，所以插件会额外用作品 API 把这件商品真实的分类（`custom_genres`）和选项补上——否则所有按分类发券（社团券、翻译券、期间活动券）都匹配不到。补的时候**价格仍用购物车里的实付价**，不拿作品页定价覆盖。

面板仅供参考，**最终金额以确认购买页为准**。

### 金额取整：逐件计算，不是对总额折算

这一条是实测出来的，差 2 円就是差在这里：

小计 1,408 円（220 + 704 + 484）用 15% 券，页面显示 **1,198 円**。
- 对总额折算：`floor(1408 × 0.85) = 1,196` ❌
- 逐件折算再相加：`187 + 598 + 411 = 1,198` ✅

也就是说 DLsite 是**每件商品单独打折、单独向下取整，然后把结果相加**。百分比券一律按这个规则算；定额券（如 300 円 OFF）仍是**整单只扣一次**。

## 数据与隐私

- 记录只存 `chrome.storage.local`，金额统一折算日元再比较，显示时按 `currency_price` 比例换回当前货币
- 网络请求仅三处：`price.maenohou.com`（background 代发）、DLsite 自身 `product.json` / `coupon.json`（同源，带登录态）
- 设置页可导出 JSON、清空、关闭记录

## 已知限制

- 券名的语言由 DLsite 决定（中文市场的券就是中文名）
- 券后价依赖页面 DOM（`.coupon_available dd.total`），DLsite 改版需同步选择器
- セット割 / まとめ買い 仅在活动数据的作品上生效（`specified_volume_sets` / `is_bulkbuy`），平时以「券的部数门槛」为主要的多部优惠
- 多部试算按当前作品单价 × N 估算，不替你挑选凑单的具体作品
